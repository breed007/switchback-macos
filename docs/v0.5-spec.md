# Switchback v0.5 release spec

**Status:** Planned · **Version:** 0.5.0 · **Target:** macOS 14+ · **Drafted:** 2026-10-04

## Summary

v0.5 makes switching one click for every kind of user. A privileged helper takes
the admin password out of switching, which also lets standard users switch. Name
handling is fixed and checked as you type, location management moves into a real
window, and Shortcuts and Focus can trigger a switch.

## Why now

Three findings from the planning review:

1. **Every switch asks for an admin password.** SCPreferences needs the
   `system.services.systemconfiguration.network` right. For a normal app that right
   resolves to `authenticate-admin-nonshared` (not shared, 30-second timeout), and
   Switchback frees its authorization after each operation. So "one click" is
   really click, password, Return. A standard user can't switch at all without an
   administrator typing their credentials.
2. **The v0.1.1 name cleanup has two bugs.** It splits emoji built with a
   zero-width joiner (`👨‍👩‍👧 Home` becomes `👨 👩 👧 Home`) and turns an invisible
   zero-width space into a visible space (`Off​ice` becomes `Off ice`). Duplicate
   detection also misses full-width lookalikes (`Ｏffice` vs. `Office`).
3. **Crossbar has moved ahead.** Crossbar v0.5.0 shipped a signed `SMAppService`
   helper, Launch at Login, and accessibility work. Switchback can reuse that helper
   design almost directly. `LocationSwitcher` was built as the seam for this swap
   (see DESIGN.md, "Future considerations").

## Personas

| Persona | Today | After v0.5 |
|---|---|---|
| Field consultant (admin, switches several times a day) | Password on every switch | One click, ⌘-number keys, Focus can switch for them |
| IT / Mac admin (deploys to standard-user fleets via MDM) | Standard users can't switch without an admin | Helper pre-approved by an MDM profile, optional admin-only policy, audit log |
| Standard user (switches between locations someone else set up) | Needs an admin's credentials | Switches freely; create, rename, and delete still need an admin |
| Automator (Shortcuts and Focus) | No integration | Switch Location and Get Current Location actions, a Focus filter |

## Decisions

Made in the 2026-10-04 planning session:

- **Privilege is split by intent.** Switching between existing locations goes
  through the helper with no prompt. Creating, renaming, and deleting keep the
  admin prompt, because they change configuration.
- **Standard users may switch through the helper.** The helper can only move
  between locations an administrator already created, which is what makes this
  acceptable. IT can require admin rights with a managed preference (F1).
- **Shortcuts and Focus integration is in scope.** The DESIGN.md non-goal still
  holds: Switchback has no rules engine. The user writes the rule in Apple's tools,
  Switchback provides the action, and every automated switch is announced (F6).
- **All four personas are first-class.** Each feature is checked against each one
  (see Test matrix).
- **The helper is a second copy of Crossbar's design, not a shared package.** Under
  the rule of three, extract it into a Swift package when a third app needs it.

## Features

### F1: Passwordless switching via a privileged helper

**Problem.** Every switch prompts for an admin password, and standard users can't
switch on their own.

**Behavior.**
- With the helper enabled, choosing a location switches immediately. No dialog.
- Without the helper, switching works as it does in v0.1.1 (admin prompt). Nothing
  breaks for people who skip setup.
- The menu shows **Set Up Passwordless Switching…** until the helper is enabled. It
  registers the helper, explains the one-time approval, and opens **System
  Settings → General → Login Items & Extensions**
  (`SMAppService.openSystemSettingsLoginItems()`).
- Create, rename, and delete always use the admin-authorized path, helper or not.

**Design.** Mirrors Crossbar's
[Backend B](https://github.com/breed007/crossbar-macos/blob/main/docs/backend-b-design.md).

- New target `SwitchbackHelper` (command-line tool, Hardened Runtime), embedded at
  `Contents/MacOS/SwitchbackHelper`, with its launchd plist at
  `Contents/Library/LaunchDaemons/com.breed007.switchback.helper.plist`
  (`BundleProgram`, `MachServices`, `AssociatedBundleIdentifiers`). Registered with
  `SMAppService.daemon(plistName:)`. It runs as root, which satisfies the right's
  `is-root` clause.
- **XPC contract.** One operation.

  | Request key | Type | Meaning |
  |---|---|---|
  | `op` | string | `"switchTo"`, the only value |
  | `setID` | string | target `SCNetworkSet` ID |

  | Reply key | Type | Meaning |
  |---|---|---|
  | `ok` | bool | committed and applied |
  | `error` | string, optional | `unknown-set`, `commit-failed`, `apply-failed`, `policy-denied`, `unknown-op` |

  No names cross the boundary. The helper rejects unknown ops, so later versions can
  add ops without breaking an older helper.
- **Security controls.**
  1. The helper pins its caller with `xpc_connection_set_peer_code_signing_requirement`:
     `identifier "com.breed007.switchback" and anchor apple generic and certificate leaf[subject.OU] = "YA83Q8FTH3"`.
     The client pins the helper the same way.
  2. The helper re-reads `SCNetworkSetCopyAll` and refuses any `setID` that isn't a
     live set.
  3. The helper can only switch. It has no create, rename, delete, or edit
     operation and must never gain one. This is what makes standard-user switching
     acceptable.
- **Admin-only policy (for IT).** A Bool `RequireAdminToSwitch`, read only from the
  managed preferences domain
  (`/Library/Managed Preferences/com.breed007.switchback.plist`), never from
  user-writable defaults. Default false. When true, the helper checks the caller's
  effective UID for admin group membership (`xpc_connection_get_euid` plus
  `mbr_check_membership`) and otherwise replies `policy-denied`, and the app falls
  back to the admin prompt.
- **Audit log.** Every helper switch goes to the unified log (subsystem
  `com.breed007.switchback.helper`): caller UID, from-set, to-set, result. Nothing is
  written to files or sent anywhere.
- **Routing.** `SwitchRouter: LocationSwitcher` sends `switchTo` to the helper when
  its `SMAppService` status is `.enabled`, otherwise to `AuthorizedSwitcher`.
  Create, rename, and delete always go to `AuthorizedSwitcher`. `LocationSwitcher`
  methods become `async`, and the controller's `perform` wraps them in a `Task`,
  replacing the GCD dispatch added in v0.1.1.
- **MDM pre-approval.** A Managed Login Items payload (`com.apple.servicemanagement`)
  with a Team Identifier rule for `YA83Q8FTH3` approves the helper with no user
  action. The README gets a sample profile.
- **Uninstall.** The cask gains `uninstall launchctl: "com.breed007.switchback.helper"`.
  Document manual removal for non-Homebrew installs.

**Acceptance.**
- Admin, helper enabled: switching shows no dialog.
- Standard user, helper enabled: switching shows no dialog; create, rename, and
  delete still require an admin's credentials.
- Helper not set up: switching prompts as before, and canceling is still a silent
  no-op.
- `RequireAdminToSwitch` set to true: a standard user's switch falls back to the
  admin prompt.
- A caller signed by anyone else, or ad-hoc, is rejected by the OS before helper
  code runs.
- An unknown `setID` returns `unknown-set` and changes nothing.

### F2: Launch at Login

**Problem.** After a restart, Switchback is gone until the user relaunches it or
adds it to Login Items by hand.

**Behavior.** A **Launch at Login** checkbox in the menu, off by default, using
`SMAppService.mainApp` (port Crossbar's `LoginItem.swift`). If the system needs
approval, the menu says so instead of failing silently.

**Acceptance.** Checking it survives a restart. Unchecking removes Switchback from
Login Items.

### F3: Name handling fixes

**Problem.** See Why now, item 2.

**Behavior.** One `LocationNameValidator`, used by the backend (the authoritative
check), the name dialog (F4), the Manage window (F5), and the reserved-name check.

- **Stored name:** replace control characters (newlines, tabs) with a space; remove
  invisible format characters except the zero-width joiner and non-joiner, which
  emoji and some scripts need; collapse runs of whitespace, including no-break
  spaces, to one space; trim; normalize to NFC; cap at 128 characters.
- **Duplicate check** compares a skeleton: NFKC (folds full-width and compatibility
  forms), all format characters removed, whitespace collapsed, case folded. Accents
  stay significant (`Résumé` and `Resume` are different names). Two names that look
  identical can't both exist.
- **Lookalike warning:** if a word mixes Latin with Cyrillic or Greek letters, warn
  ("Looks like 'Office' but uses Cyrillic letters"). Warn, don't block.
- **Reserved name:** the "Automatic" check compares skeletons too.
- Renaming a location to a case-only variant of its own name (`office` to `Office`)
  stays allowed.

**Acceptance.** Unit tests in a new `SwitchbackTests` target (the validator is pure
and needs no privileges) cover:
- the family emoji survives intact
- `Off​ice` with a zero-width space is stored as `Office`
- `Ｏffice` is a duplicate of `Office`
- NFC and NFD `Café` are duplicates
- `Résumé` and `Resume` are not
- a pasted multi-line block becomes one line
- 129 characters is rejected
- a Cyrillic `Оffice` produces a warning

### F4: Name checks as you type

**Problem.** Today you type a name, click OK, get a separate alert, and start over
from the menu.

**Behavior.** The name field validates on every keystroke against the current
location list. OK is disabled while the name is invalid, and a line under the field
says why (empty, too long, already used by "X", reserved). Lookalike warnings show
but don't disable OK. If the backend still rejects the name (say, a location was
added in the meantime), the dialog reopens with the typed text intact.

**Acceptance.** Typing an existing name disables OK and names the clash. No path
loses typed text.

### F5: Manage Locations window

**Problem.** Rename and delete sit three levels deep in a submenu, the same kind of
burial Switchback exists to fix.

**Behavior.** **Manage Locations…** in the menu opens a window with:
- a table of locations showing the current one, each location's service count, and
  its primary service
- inline rename (double-click), using the F3 and F4 checks
- add (+) and delete (−) with confirmation; delete is disabled for the current, the
  last, and the protected location, with a tooltip saying why
- drag to reorder; the order is stored in user defaults by set ID (IDs are stable,
  names aren't) and the menu follows it; new locations go to the end, and unknown
  IDs sort alphabetically after the ordered ones
- for standard users, a note that changes need an administrator (the admin prompt
  appears on commit)

The Manage Locations submenu goes away. The menu stays the fast path for switching.

**Acceptance.** Every rename and delete from v0.1.1 is reachable from the window.
Reordering persists across relaunch and shows in the menu. The window works from
the keyboard alone (Tab, Return to rename, Delete with confirmation). VoiceOver reads
each row's name, current state, and service count.

### F6: Switch confirmation and live details

**Problem.** A successful switch is silent. That's fine when you clicked, but not
when Shortcuts or Focus switched for you, which is the "why did my network just
change?" worry in DESIGN.md.

**Behavior.**
- After any switch, the status item shows the location name next to the icon for
  about three seconds.
- An optional **Show Location Name in Menu Bar** checkbox keeps it there.
- The menu shows a detail line under the current location, read when the menu
  opens: primary service, IPv4 address, and DNS servers (from
  `State:/Network/Global/IPv4` and `State:/Network/Global/DNS`, no privileges
  needed).
- Switches started by Shortcuts or Focus post a notification ("Switched to Office
  by Work Focus"). Notification permission is requested at the first automated
  switch. If it's denied, the status-item flash is the only signal.

**Acceptance.** Each switch source (menu, Shortcut, Focus) produces the documented
feedback. The detail line matches `scutil --nwi` once DHCP settles.

### F7: Shortcuts, Spotlight, and Focus

**Problem.** Switching is manual every time, even for people whose location follows
their schedule.

**Behavior.**
- **Switch Location** action: pick a location; switches through `SwitchRouter`.
- **Get Current Location** action: returns the current location for use in
  Shortcuts conditions.
- **App Shortcuts** phrases for Spotlight and Siri ("Switch Switchback location to
  Office").
- **Focus filter:** in a Focus's settings, choose a location to switch to when that
  Focus turns on. Ending a Focus changes nothing.
- Global keyboard shortcuts come for free: Shortcuts can assign a key combination to
  a Switch Location shortcut, so Switchback needs no hotkey code of its own.

**Design.**
- `LocationEntity: AppEntity` (ID is the set ID, plus a display name), with an
  `EntityQuery` and `EntityStringQuery` over the unprivileged read model.
- The intents live in the main app target, not an extension, so the helper's
  single-identifier signature pin covers them.
- If the helper isn't enabled, a Shortcut run by hand falls back to the admin
  prompt. A Focus filter never prompts, since nobody is watching: it skips the
  switch and posts a notification pointing to **Set Up Passwordless Switching…**.
- Make the filter's `location` parameter optional with a nil default, so whatever
  the system sends when a Focus ends causes no switch. Confirm the actual
  end-of-Focus behavior in milestone 5.

**Acceptance.** Each action appears in Shortcuts with the location list. A Focus
switches the location when it turns on and leaves it alone when it ends. With the
helper missing, a Focus produces a notification and no dialog.

### F8: ⌘1 to ⌘9 in the menu (stretch)

The first nine locations, in F5 order, get ⌘1 to ⌘9 key equivalents while the menu
is open.

## Out of scope for v0.5

| Idea | Why not now |
|---|---|
| Duplicate a location | Copying services that hold saved secrets (VPN) is unproven. First candidate after v0.5. |
| `switchback://` URL scheme | Any web page could trigger a network change. App Intents cover scripting safely. |
| Blocking lookalike names | A mixed-script name can be legitimate. Warn only (F3). |
| Shared Swift package with Crossbar | Rule of three: two copies so far. |
| Returning to the previous location when a Focus ends | Needs remembered state and could surprise people. Revisit with feedback. |
| A custom global hotkey | Shortcuts already provides one (F7). |

## Milestones

Ship as a single v0.5.0. Internal order, riskiest first:

1. **Helper spike.** Build `SwitchbackHelper`, register it, and prove the approval
   flow with a signed build, both as an admin and as a standard user. Prove one real
   switch by ID over XPC. Crossbar already proved the signature pin and the root
   write; the approval steps are what to verify first.
2. **Foundations.** `SwitchbackTests` target, `LocationNameValidator` (F3), Launch at
   Login (F2), housekeeping renames.
3. **Router and policy.** `SwitchRouter`, async `LocationSwitcher`,
   `RequireAdminToSwitch`, audit log, setup flow (F1).
4. **UI.** Name checks as you type (F4), Manage window (F5), confirmation and
   details (F6), ⌘ keys (F8).
5. **App Intents** (F7), once the helper is solid.
6. **Docs and release.** README, DESIGN, PRIVACY, and CLAUDE.md; `release.sh` signs
   and notarizes the embedded helper; cask `uninstall` stanza; QA pass against the
   test matrix.

## Milestone 1 results (2026-10-04, macOS 27.0.1)

Built on branch `v0.5/helper-spike`. The helper runs from a Debug build signed with
the Developer ID (`scripts/dev-build.sh`) and is driven from Terminal through
debug-only flags in the app binary (`Switchback --helper-status`, `--helper-register`,
`--helper-switch <setID>`, `--helper-selftest`). Those flags run inside the signed
app, the only caller the helper accepts.

**Verified**

| Check | Result |
|---|---|
| Bundle layout and signing | Helper at `Contents/MacOS`, plist at `Contents/Library/LaunchDaemons`; both Developer ID, Hardened Runtime, team `YA83Q8FTH3`; each passes the other side's requirement |
| Registration and approval | `notFound` → `requiresApproval` → `enabled`; approving it prompted the admin for their password |
| On-demand launch | launchd starts the helper on the first call and it exits with code 0 after 60 idle seconds |
| Root write | No-op switch (current set re-asserted, commit and apply) with no password |
| ID validation | An unknown set ID is refused with `unknown-set` and nothing changes |
| Caller pin | An ad-hoc caller is rejected; a caller signed with our team certificate under a different identifier is rejected; neither reaches the handler |
| Audit log | `uid 501 switch <from> -> <to>: ok`, notice level, set IDs public, names never logged |

**Findings**

- `SMAppService.register()` for a daemon throws "Operation not permitted" even
  though registration succeeded into `.requiresApproval`. `HelperClient.register()`
  treats that as success. Without the fix, the setup menu item showed an error
  instead of the approval instructions.
- A rejected caller sees "Connection interrupted" on macOS 27. Crossbar's spike
  on 26.5 reported "Peer Forbidden". Either way the message never reaches the
  helper.
- In zsh, `log` is a shell builtin. Scripts that read the unified log must call
  `/usr/bin/log`.
- The team has two Developer ID Application certificates, so
  `codesign -s "Developer ID Application"` is ambiguous. Sign by SHA-1, or let
  Xcode choose.

**Not yet verified** (moved to the milestone 6 QA pass; these block release)

- A real switch between two locations from the menu. This needs a second location
  and a moment when dropping the VPN service in Automatic is acceptable.
- Standard-user switching, and whether a standard user can approve the helper.
  This needs a standard account.
- The **Set Up Passwordless Switching…** menu flow end to end. Registration was
  driven from the debug flags.

## Milestone 2 results (2026-10-04)

- **F3, name handling.** `LocationNameValidator` with 21 unit tests in
  `SwitchbackTests` (`scripts/test.sh`), covering every F3 acceptance case. With
  the v0.1.1 joiner bug planted back in, the emoji test fails, so the suite catches
  the regression it was written for. The backend validates against live names
  before committing, and `LocationModel.isProtected` compares skeletons.
- **F2, Launch at Login.** A menu item with a "Needs Approval" state that opens
  Login Items. Turned on and back off on the real system; it registered without
  needing approval.
- **Housekeeping.** `.cancelled` is now `.canceled`. `StatusMonitor` watches the
  global IPv4 setup and state keys instead of the dead `Setup:/` key.
- **Update path.** The helper stayed approved after a new build replaced the app at
  the same path, so an update shouldn't need re-approval.

Not yet verified (added to the milestone 6 QA pass): creating and renaming
through the backend with the new rules (needs an admin password; the rules
themselves are unit-tested), and the Launch at Login menu item itself (it was
driven through a debug flag).

## Milestone 3 results (2026-10-04)

- **Router.** `LocationSwitcher` is async. The admin-prompt backend runs its
  blocking commits on one serial queue, so a password panel never ties up a Swift
  concurrency thread and two commits can't race. `SwitchRouter` falls back to the
  admin prompt when the helper can't be reached, refuses by policy, or doesn't know
  the op. It doesn't fall back when the helper ran and the switch itself failed.
  10 unit tests use fakes, and a real routed no-op switch went through the helper.
- **Policy.** The helper reads `RequireAdminToSwitch` from the managed preferences
  file on every request (only a root-owned file counts) and checks admin membership
  only when the policy is on. 10 unit tests cover parsing, the ownership guard,
  admin detection against real accounts, and the decision table. Admin detection
  uses `getgrouplist` and matched `dsmemberutil` for four accounts.
- **Setup states.** The menu shows **Set Up Passwordless Switching…** before
  registration and **Approve Passwordless Switching…** while approval is pending.
- **Hardening.** The helper refuses malformed set IDs (anything but letters,
  digits, and hyphens, or over 64 bytes) before touching preferences or writing the
  log. Found while verifying: a newline in a bogus ID had split an audit-log entry
  in two. Verified against the rebuilt helper; two unit tests cover it.
- **Mutation checks.** With each of three bugs planted (unknown-set falling back,
  the root-owner check disabled, the policy always allowing), the suite failed.
- **Update gotcha.** Replacing the app doesn't stop a running helper. The previous
  binary keeps serving until it has been idle for 60 seconds.
- 43 unit tests, no compiler warnings.

Not yet verified (added to the milestone 6 QA pass): a `policy-denied` refusal
end to end (needs a managed `RequireAdminToSwitch` and a standard user), admin
detection through nested directory groups (for example AD "domain admins"), the
real app falling back to the admin prompt, and the two setup menu states.

## Milestone 4 results (2026-10-04)

- **F4, name checks as you type.** The New Location dialog validates on every
  keystroke. OK is disabled while the name can't be saved, and a line under the
  field says why. If the backend still rejects the name, the dialog reopens with

- **F5, Manage Locations window.** A table of locations, built in code. Rename in
  place (double-click or Return) with the same live checks; Escape cancels. Delete
  (− or the Delete key) asks for confirmation, and is disabled with the reason in

- **F6, confirmation and details.** The current location gets a live details
  line: primary service, address, DNS (matched `scutil --nwi` and `scutil --dns`).
  After a switch from any source Switchback notices, the location name shows next
  to the icon for three seconds. **Show Location Name in Menu Bar** keeps it there.
  Notifications for automated switches move to milestone 5, which adds the only
  automated sources.
- **F8.** ⌘1 to ⌘9 for the first nine locations, in the user's order.
- **Fix.** Choosing the location you're already on no longer starts a switch.
  Without the helper, it used to ask for a password for no change.
- **Finding: hidden interfaces.** macOS hides services on interfaces whose driver
  has `HiddenConfiguration = Yes` in the I/O Registry (here, the internal USB-C
  networking interfaces en4 to en6). Switchback first counted 7 services against
  `networksetup`'s 4. It now reads the same flag through IOKit, and the counts and
  first service match.
- **Checks.** 56 unit tests (ordering, rename and delete rules, name feedback, the
  details line). The real menu and window wiring were checked through Debug dumps
  (`--menu`, `--manage`, `--manage-sample`), including every row kind.

Not yet verified (added to the milestone 6 QA pass): anything that has to be seen
or clicked. That means layout of the window and dialog, renaming in place, drag
to reorder, keyboard operation, VoiceOver speech, the name flash after a real
switch, and ⌘ keys with the menu open.

## Risks and open questions

- **Daemon approval for standard users.** On an unmanaged Mac, approving a daemon in
  Login Items & Extensions should need an administrator once. Milestone 1 confirmed
  that it prompts an admin for their password; the standard-user case is still
  untested.
- **MDM payload.** Check the Managed Login Items payload and the managed
  `RequireAdminToSwitch` key against a real MDM enrollment.
- **App Intents in an agent app.** Confirm that intents and Focus filters run when
  Switchback, an `LSUIElement` app, isn't already running. Launch at Login makes
  this matter less, but it shouldn't be required.
- **End of Focus.** Confirm what the system sends when a Focus ends (see F7).
- **Notification permission timing.** The first automated switch is an odd moment to
  ask, and there's no better hook today. Accept it for v0.5 and revisit.
- **Helper and app version skew.** The op contract only grows and the helper rejects
  unknown ops. Test a new app against an old helper and the reverse.
- **System-wide effect.** Locations apply to the whole Mac, so a standard user's
  switch affects every account on it. That's how locations work; the README should
  say so.
- **"Automatic" identity.** The protected-location check is still name-based,
  though now skeleton-matched. A default location renamed in System Settings loses
  that protection. The identity-based delete guards from v0.1.1 still apply.
