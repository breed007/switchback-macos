# Switchback v0.7 release spec

**Status:** In progress · **Version:** 0.7.0 · **Target:** macOS 14+ · **Drafted:** 2026-11-12

## Summary

v0.7 tells you when a new version of Switchback is out, if you ask it to. It's the
same update check as Crossbar 0.7 (see Crossbar's `docs/v0.7-spec.md`), fitted to
Switchback's menu. It checks GitHub's latest release at most once a day, adds a menu
item when there's a newer one, and sends you to the release page or the Homebrew
command. It never downloads or installs anything. The version keeps step with
Crossbar.

## Decisions

These match Crossbar's v0.7 decisions:

- **Notify only.** No downloads, no self-replacement, no Sparkle. The helper makes a
  self-update security-sensitive, Switchback has no third-party dependencies, and a
  self-update would leave Homebrew's record of the version wrong.
- **Off until you turn it on.** The README and PRIVACY.md promised no network calls.
  Both now say exactly what the check requests and sends.
- **One request, nothing about the Mac.** A GET to
  `https://api.github.com/repos/breed007/switchback-macos/releases/latest` with an
  ephemeral session, no cookies, and a fixed User-Agent (`Switchback`).
- **Homebrew installs get the Homebrew command** (`brew upgrade --cask switchback`).
- **IT can turn it off** with a managed `DisableUpdateCheck`, added to the sample MDM
  profile next to `RequireAdminToSwitch`.
- **Two copies.** `UpdateCheck.swift` is Crossbar's file with Switchback's `Product`.
  `UpdateChecker.swift` differs in its preferences type, its notification name, and
  demo mode (Switchback's demo shows no update item, so it needs no demo release).
  Extract a package when a third app needs them.

One difference, because Switchback is a menu, not a popover:

- **No one-time question.** A menu can't hold a two-button question, and an alert at
  launch is the kind of unprompted interruption Switchback avoids. The unchecked
  **Check for Updates Automatically** item is the opt-in, visible every time the
  menu opens.

## Scope

| # | Feature | Priority | Size |
|---|---|---|---|
| U1 | Opt-in daily update check | Must | M |
| U2 | "Switchback 0.7.1 Is Available…" menu item, Homebrew-aware | Must | S |
| U3 | Menu: Check for Updates Automatically, Check for Updates…, managed off | Must | S |

Out of scope: automatic downloads or installs, a beta channel, update notifications.

## Features

### U1: Opt-in daily update check

- Preference `CheckForUpdates`: unset or off until the user turns it on.
- When on, Switchback checks at launch and hourly whether 24 hours have passed since
  the last attempt. A failed check waits for the next day and says nothing.
- Only a `tag_name` like `v0.7.1` and an `html_url` under
  `https://github.com/breed007/switchback-macos/releases/` are accepted. Switchback
  never opens a URL that fails this check.
- Versions compare numerically by component; a tag that doesn't parse is ignored.
- The newest version seen is stored, so the menu item survives a relaunch and goes
  away once the installed version catches up.

### U2: Available item

- With a newer version known, the menu's settings section starts with
  "Switchback 0.7.1 Is Available…".
- Choosing it opens the release page, or, for a Homebrew install (a Caskroom folder
  for `switchback`), an alert with the `brew` command and **Copy Command**,
  **Release Notes**, and **Cancel**.

### U3: Menu items

- **Check for Updates Automatically** (checkmark) and **Check for Updates…**, just
  above Quit.
- Check for Updates… asks GitHub right away, whether or not automatic checks are on.
  It opens the update flow if there's a newer version; otherwise it says "Switchback
  is up to date" or "Couldn't check for updates".
- With `DisableUpdateCheck` forced to true by MDM, neither item appears and no request
  is made.

## Behavior worth knowing

- The menu item shows the last result of any check, scheduled or manual, until the
  installed version catches up. Turning scheduled checks off stops new requests; it
  doesn't hide a newer version you already know about.
- Simultaneous checks (Check Now while the timer fires) share one request.
- A managed `CheckForUpdates` forced by MDM wins over the user's choice, as managed
  preferences do. Only `DisableUpdateCheck` is documented for administrators.

## Housekeeping

- `scripts/release.sh` gets Crossbar's release checks: refuse a binary with Debug
  flags, and a fatal Gatekeeper assessment before packaging.

- README: features list, Privacy, and the MDM section. PRIVACY.md: an Update check
  section. CHANGELOG, version 0.7.0 (build 5). CLAUDE.md note.
- `--update-check [version]` Debug flag for a live check.
- Regenerate the menu screenshots for the new items.

## Risks

- **GitHub rate limits:** 60 unauthenticated calls an hour per IP; one a day per Mac
  is far below that.
- **Untested hands-on:** Homebrew detection on a real Homebrew install, and the
  managed preference delivered by a real MDM profile.
